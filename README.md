# dsh-bili-duty

让 AI **每天替你在 B站 刷一轮**：按热度挑出值得看的、私信给你；你看完回几个分数，
它把口味**回流成搜索关键词**；回 `/命令` 还能把私信当控制台用；
桌面托盘里还有个小窗口看着它有没有在干活。

这是围绕 [DSH（DeepSeek Harness）](https://github.com/deepseek-ai) 两个插件搭的**外围工具集**。
上游插件不在本仓库（各自是独立仓库）：

| 上游插件 | 作用 |
|---|---|
[dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll) | 定时起一个 headless 轮：读字幕/抽帧、挑视频、写日报、发私信 |
[dsh-video-storyboard](https://github.com/SAOS-3624/dsh-video-storyboard) | 从 B站 自带故事板裁帧，让模型"看见"画面 |

> 本仓库只做三件上游没做的事：
> ① 把「**你的评价**」变成「**下一轮的搜索词**」；② 把私信变成**可操作的控制台**；③ 让这一切**不出声地**跑在托盘里。

## 1. 全景：一次完整的循环

```
          ┌──────── 值班轮（上游插件 spawn，我们只加了闸）────────┐
 开窗时 ▶ │ 多源召回 → 读字幕/抽帧 → 挑一批 → 写日报 → 私信给你 │
          │ 手里只有 B站 只读工具：没有文件系统、没有 shell      │
          └──────────────────────┬─────────────────────────────┘
                                     │ 私信：1=10 3=11 5=-1 4 调色真舒服
          ┌──────────────────────────▼─────────────────────────────┐
          │ 私信控制台（每 1 分钟）                                 │
          │  ① 拉私信 → ② 记账(评分.mjs) → ③ 回执                  │
          │  → ④ 发追问 → ⑤ 逐条分派                                │
          │  优先级：关键词语句 > 追问回答 > /命令 > 打分 > 闲聊     │
          └──────────────────────────┬─────────────────────────────┘
                                     │ 11→提词 ｜ -1→降权→删词 ｜ 文字评价进缓冲区
          ┌──────────────────────────▼─────────────────────────────┐
          │ config.json:keywords → 下一轮按新方向搜                 │
          │ duty.md 的 PREFS 区块每轮重算（你的规矩 + 判据统计）     │
          └────────────────────────────────────────────────────────┘

  托盘控制台（常驻）：每 15 秒替上面这圈兜一次底，并把状态摊成一个小窗口
```

三条链路的分工，和「谁读谁写」的关系：

| 链路 | 入口 | 决定什么 | 落盘到 |
|---|---|---|---|
评价闭环 | `评分.mjs` | 搜索关键词从哪来 | `config.json:keywords`、`ratings.jsonl`、`降权.json`、`待追问.json` |
私信控制台 | `私信控制台.py` | 什么时候扫、扫到的东西怎么分派 | `console-state.json`、`console.log`、`chat-history.jsonl` |
对账补记 | `对账补记.mjs` | 报告里的额度算得对不对 | `out/<日期>.md` |

## 4. 值班轮：它凭什么"看见"和"挑"

### 4.1 最小权限 profile

值班轮是个**没人看守**的 headless 轮。默认 headless profile 只关了 `hmr` / `credentials` / `authorization`，
工具一个没动 ⇒ 那一轮手里握着整台电脑。`patches/cordis.patch.yml` 的思路不是"叮嘱它别乱来"，
而是**根本不给它那些手**：

| 关掉 | 留下 |
|---|---|
文件系统、shell、pwsh、jobs、subagent、workflow、web、`bili_reply` | B站 MCP 的只读工具 + 收窄写口的 `duty_*` 工具 |

写日报 / 判重表 / 归档全走**固定路径的窄口工具**（`duty_report_append` 等），
所以"没有文件系统"并不妨碍它干活。

### 4.2 白名单是"不注册"，不是"拒绝"

插件把白名单拼成环境变量 `BILI_MCP_TOOLS` 交给 MCP 进程；**没列出的工具压根不会注册**，
模型连"我能不能用"这个问题都看不到。几个关键规则：

- 看画面/听完的：`bili_cover` / `bili_frames` / `bili_subtitle` / `bili_danmaku`
- 评论工具 `bili_reply`：只有 `autoComment` 或 `replyToComments` 打开、**且不是"只私信"**时才下发
  （有过"开关关了但配置里还留着 true ⇒ 评论照发"的事故，所以这条是硬判断）
- 榜单类 `bili_rank` / `bili_hot_videos` / `bili_weekly_hot` / `bili_video_zones`：
  补丁里放进了 `_ALWAYS`，**无论白名单怎么写都放行** —— 都是只读接口

### 4.3 候选从哪来（为什么不能只用 `order=click`）

`order=click` 是**全时段播放量**排序 ⇒ 候选永远落在历史头部，反复端上同一批，
候选池几天就枯竭。所以召回改成**多源**：

```
① bili_rank(category, day=3|7)   ← B站 官方"近期热度"榜（质量 + 近期动量）
② bili_weekly_hot                ← 周榜，偏新片
③ bili_search(kw, order=pubdate) ← 新片探测（时间窗放到近 30 天）
④ bili_search(kw, order=click)   ← 老牌爆款的兜底
        ↓ 合并去重（seen.md 判重）
排序用「日均播放 = 播放量 ÷ 发布天数」
```

日均播放这一条同时治两个毛病：**太老的**，播放量再高也被分母摊薄；**太新没人看的**，分子太小自然沉底。
> 这些是写进章程（`duty.md`）和 `bili_search` 用法说明里的**策略**，不是代码里的排序器 ——
> 模型读章程后自己按这个口径挑，这样"策略"改了不用改代码。

### 4.4 发私信前的两道闸（代码级，命中就真发不出去）

都在 `patches/mcp_server/patched.py` 的 `bili_send_message` 里，数据来自同一个 `view` 接口
（**零额外请求成本**）：

1. **链接体检**：BV 号**大小写敏感**。`BV1Ms411m7Pf`（东方原曲合集）和 `BV1ms411m7Pf`
   （【兽人】I GOT YOU）是两个不同的真实视频。拿真标题和私信里那段文字比相似度，对不上 ⇒ **拒发**并回报真实标题。
2. **投递闸门**：屏蔽词 / 屏蔽 UP / 时长上限 / 播放量下限。
   - 闸门**默认关闭**（时长 0 = 不限、播放量 0 = 不限）—— 185 播放的原创动画确实可能比 200 万播放的更好
   - **合集/课程豁免**：793P、2800 分钟的合集不当"超长"处理
   - 闸门**永不 fail-open**：状态未知时按"拦"处理

### 4.5 日报与额度口径

宿主用**日报里 `### BV` 的行数**算"今天挑了几条"，据此扣额度。上游 `writeRoundNotesToReport()`
用 `indexOf('## 投递')` 找第一个投递段然后把它之后全砍掉 ⇒ 只要有一轮写过投递段，
后面每轮追加的条目都会在下一轮收尾时被吃掉（实测：判重表 20 条 / 报告 6 条）。
补丁改成 `lastIndexOf` + "只有当最后那个投递段后面没有别的 `###` 才替换"，
在此之前由 `对账补记.mjs` 顶住（见 §8）。

## 5. 评价闭环 `评分.mjs`

你发一条私信，它要决定三件事：**这是给哪条视频的**、**多少分**、**要不要动关键词**。

### 5.1 一条消息怎么解析

```
"3＝11 有深度"          → { n:3, score:11, reason:"有深度" }
"1=10 3=9"              → 两条
"4 调色板真舒服"         → { n:4, score:null, reason:"调色板真舒服" }   ← 纯文字评价
```

实现上两个正则：

```js
PAIR      = /(?:^|[^\d\w])(\d{1,2})\s*[=:：]\s*(-?\d{1,2})(?!\d)/g   // 编号=分数
TEXT_ONLY = /^\s*\[?(\d{1,2})\]?\s*[，,、.。:：\-\s]+([\s\S]+)$/      // 编号 + 一句话
```

两个容易踩死的细节：

- **必须做全角归一化**：中文输入法打出来的是 `＝`、`：`、全角数字。实测「3＝11 有深度」曾被
  当成闲聊，11 分直接丢。这里用 `[\uFF01-\uFF5E] − 0xFEE0` 的**等长映射**，
  顺带把 `\u3000`（全角空格）和 `\u2212`（减号）也换掉。
- **不能用 `normalize('NFKC')`**：那会把中文标点也改掉（`，` → `,`），等于篡改你的原话，
  画像里就会出现被改过的句子。
- 因为换全是**等长**的，所以可以"在归一化后的串上取下标、回原文里切片" ——
  `reason` 永远是你打的原文（见 `parseMessage` 里 `raw.slice(p.end, stop)`）。

分数区间 `-1 … 11`，超出就 clamp；编号限定 `1…60`。

### 5.2 怎么知道 `3` 是哪条视频

私信里的批次长这样：`[1] 标题 … BV…`，一组 `[N] BV`。`buildBatches()` 把它们还原成
`[{at, items: Map<n, {bvid, title, up}>}]`，再用**消息时间戳**找"这条评价属于哪一批"
（`batchForMsg`：取该时间之前最近的一批）。找不到批次 ⇒ 跳过，不乱猜。

### 5.3 11 分：从你的理由里提词

思路：**你夸的点通常就在标题里**，所以取「理由」和「标题 / UP 名」的公共子串，
既准（一定是这条视频的特征）又不用上分词器。
`extractGoodKeywords` 的流水线：

```
理由 ──最长公共子串(≤10字)──▶ 剥标点 ──▶ 长度 ≥2 ?
                                          │ 是
                                          ▼
                              顺着标题往右补全（最多 +3 字）
                              理由说"空岛"，标题是"仅一格方块的空岛生存？" ⇒ 取「空岛生存」
                                          ▼
                      剥掉「第/个/集/期/版/部」前缀 → 长度 ≥2 → 过停用词 → 过冗余判定
                                          ▼
                                   最多产出 2 个词
```

冗余判定 `isRedundant` 的三条规则很关键（否则关键词会被"同义词"淹掉）：

| 情形 | 判定 | 例 |
|---|---|---|
已有 `泰拉瑞亚`，新词 `泰拉` | 多余（被包含） | 丢弃 |
已有 `泰拉瑞亚`，新词 `泰拉瑞亚啊` | 多余（多说了 1 字） | 丢弃 |
已有 `泰拉瑞亚`，新词 `泰拉瑞亚的电路` | **有价值**（更具体） | 保留 |

关键词上限 `KW_CAP = 24`（太多了每轮也只能用一个词）。

### 5.4 -1 分：两级降权，不一次杀品类

以前「理由里出现的关键词」全部当场删 —— 一句"泰拉瑞亚那条太吵"就能把整个品类干掉。
现在两级：

| 第几次 -1 | 动作 |
|---|---|
第 1 次 | **软降权**：写进 `降权.json`，章程里写成"还能推但排后面" |
第 2 次 | **真删**：从 `config.json:keywords` 移除，并清掉降权记录 |

想立刻删就用 `/kw del 词` —— 你说了算。

### 5.5 纯文字评价：先缓冲，再学习

一句随口的话**不该立刻改搜索方向**（会带偏），但也不能白丢。所以：

```
"4 调色板真舒服"  ──▶  ratings.jsonl 里记一条 {score:null, polarity, learned:false}
                      （这就是"缓冲区"：台账里 score===null 且未 learned 的行）

攒够 LEARN_MIN=3 条（或你发 /learn）──▶ 学一次：
   ① 把这几条文字两两求最长公共子串，出现 ≥2 条的词块才算"你反复在说"
   ② 判断极性：正向词表 − 负向词表 的票数（判断不了 = unknown，直接丢）
   ③ 正向的加进 keywords，负向的从 keywords 删掉
   ④ 只提过一次的 —— 只写进画像，标"只出现一次"，不动关键词
   ⑤ 全部标 learned:true，学过的不会重复学
```

⚠️ 不能用滑窗 n-gram：那会把「泰拉瑞亚的电路」切成「泰拉瑞亚的电」「拉瑞亚的电路」两个残词
（演练里真翻车过）。改成**两两求最长公共子串 + 合并重叠**（共享 ≥3 字即视为同一个词的错位版本）。

### 5.6 提不出词就追问，不静默失败

`3=11 有深度` 这种 —— "有深度"跟标题没交集，一个词都提不出来。分记了、什么都没学到，
使用者只会看到"怎么没有回复"。所以**把候选摆到你面前让你选**：

```
【怎么好】1 有考据 2 讲得清楚 3 选题妙 4 制作精良     ← 固定判据词（进统计，不动关键词）
【加哪个词】5 儿童漫画 6 艺术家                      ← 从标题里切出来的候选（选中才进关键词）
```

回 `1 5` 就行，也可以直接说一句话。组成：

- **判据词表** `判据统计.json`：`怎么好` / `差在哪` 各 4 个默认项，可改
- **候选词** 来自 `titleCandidates(标题)` —— 没有分词器，用"按字符类别切块"这套土办法：

```
【泰拉瑞亚】32位计算机电路 RISC-V CPU  → 泰拉瑞亚 / 计算机电路 / RISC-V
儿童漫画家杀死角色？艺术家能摆脱政治立场吗 → 儿童漫画 / 艺术家 …
```

  规则：汉字块 ≥2 字或英文/数字串 ≥3 字；块长 ≤6 直接用，>6 取前 4 字（主题一般在开头）、
  块长 ≤10 的整块也留一份；剥掉首尾虚词（`EDGE`）；以虚字/半句开头（`BAD_HEAD`）的剥一刀再试；
  剥过头（<4 字残片）丢掉；`4K60`/`v1.7.0` 这类"字母+数字短串"是画质/版本标签，丢；
  最后**短词优先**（已被更短候选包含的长词一律不要），最多 3 个。

- **同时只挂一个**：挂着的没回答且未超 24 小时就不再叠；超时自动失效
- **打分的解析优先级高于追问**：`1=10 3=9` 永远不会被当成"回答"吞掉

### 5.7 幂等与并发（两条去重线 + 一条交接线）

| 机制 | 防的是什么 |
|---|---|
`scoring-state.json:processed` 存消息 id | 同一条私信被扫两次 |
台账里 `${bvid}|${date}|${score}` 三键去重 | 历史数据（没有 msgKey 的那些）重跑也不会重复记账 |
`BILI_SKIP_MSG_KEYS` 环境变量 | **控制台用来回答追问的那条消息**不是评价，别记账（以前会记出一条 `note="4"` 的垃圾行） |

### 5.8 回执协议：`__FEEDBACK__`

以前文字评价静默落进缓冲区，一个字都不回 —— 使用者连着问"为什么没有回复"。
现在 `评分.mjs` 记完账在 stdout 末尾打一行**机器可读**的：

```
__FEEDBACK__ {"rows":2,"scores":[...],"texts":[...],"asks":1,"added":["可玩性强"],"removed":[]}
```

控制台解析它，翻译成一句人话回给你：

> 记下 2 条打分：★11 · 10分；记下 1 条文字评价（「可玩性强」…）→ 进缓冲区；
> 关键词 +可玩性强；1 条提不出词，等会儿追问你

## 6. 私信控制台 `私信控制台.py`

### 6.1 一轮扫描的 8 步

```
1. acquire_lock()            拿不到锁就跳过本次（O_EXCL，TTL 300s）
2. fetch_msgs(20)            拉私信；成功就写心跳（lastScan / scans+1）
3. 一条别人发来的都没有?     ⇒ 直接收工，下面全不做
4. 顺手对账                   跑 对账补记.mjs（纯读文件，没缺口零成本）
5. 顺手刷偏好                 跑 偏好.mjs（把你的规矩/判据渲染进章程）
6. 记账 + 回执               有 fresh 才跑 评分.mjs（带 BILI_SKIP_MSG_KEYS），
                             再把 __FEEDBACK__ 翻成人话回给你
7. 发追问                     有挂起且未 asked 的追问 ⇒ 发出去并标 asked
8. 逐条分派 fresh 消息        见 6.2
```

### 6.2 逐条分派的优先级（顺序即优先级）

```
① parse_kw_command(text)      加词/删词语句（"加词：可玩性强"）→ 处理并回复
② 回答追问                     裸数字只在「已经问出去」时才当答案；
                               显式 /答 则任何时候都算（没有追问时回一句提示）
③ /命令                        /debug /kw …（cmd[0]=="ERR" ⇒ 回"没有这个命令"）
④ 打分 / 纯文字评价            looks_like_review() ⇒ 静静记账，**不回话**（避免答非所问）
⑤ 其他                         → 当「简化版对话」回一句
```

> ① 这一层是后补的：以前 `加词：可玩性强` 会掉进"文字评价"被静默记账 ——
> **词没加、追问没关、一个字都不回**。指令必须比评价优先。

| 发 | 作用 |

`/status` `/cost` | 额度与窗口 / 今天花了多少（走 `刷视频账单.mjs`） |

### 6.4 「简化版对话」

不打 `/` 的普通话，会起一个 headless 轮回你，但只在**该轮没有值班轮在跑**时：

- 用独立的 overlay（`console-chat-overlay.yml`）+ 人格 + 最近 5 轮历史拼提示词
- `duty_busy()` 只看 `run-lock.json` 的 **pid**（不看文件新旧 —— 跑完那刻文件也是刚写的）
- 让路时直接回："我正刷着B站呢，等这一轮跑完再答你（也就几分钟）。"
- 回复统一 `clean_reply()` 洗一遍，按 `DM_LIMIT=480` 字分片、最多 4 片、每片之间 sleep 1 秒防风控

### 6.5 可靠性与自愈

| 机制 | 说明 |
|---|---|
跨进程锁 | 计划任务每分钟一次，碰上上一轮没跑完会**重复回同一条命令**（实测 `/kw` 回了两次）⇒ 拿不到锁就跳过 |
心跳 | 每轮成功拉一次私信就写 `lastScan` / `scans` —— `/status` 的新鲜度、托盘的存活判断都靠它 |
失败告警 | 连续失败 **3 次**才私信告警一次（登录过期 / 接口风控），告警过就不再刷屏 |
崩溃留痕 | pythonw 没有 stderr ⇒ 顶层 `except BaseException` 把 traceback 写进 `console.log` |
`--simulate` | 真正只读：`SIMULATE` 全局让所有落盘函数空转（有过"预览模式把闸门改真了"的事故） |

## 7. 托盘控制台 `托盘控制台.py`

### 7.1 窗口结构

```
┌──────────────────────────────────────────────┐
│ 今天 8/24 · 关键词 8 · 轮询每 15 秒 · 宿主在跑 │  ← 状态行（每 3 秒重建一次）
├──────────────────────────────────────────────┤
│ 立刻扫一次 打开DSH 启动宿主 命令行 暂停轮询 打开报告 刷新 │
├───────────────┬──────────────────────────────┤
│ 待回答的追问   │ 关键词（可增删）/ 屏蔽词（可增删） │
├───────────────┴──────────────────────────────┤
│ 投递闸门（时长上限 / 播放量下限 / 应用）        │
├──────────────────────────────────────────────┤
│ 最近台账                                       │
└──────────────────────────────────────────────┘
```

关窗 = **缩到托盘**（轮询继续），托盘菜单里有「显示窗口 / 启动宿主 / 关闭宿主 / 暂停轮询 / 打开命令行 / 退出」。

### 7.2 线程与刷新

界面线程只管画：状态区每 **3 秒** 重建一次（全是读本地文件，很便宜），
按钮点击先进队列、由 300 ms 的泵消费。另有一个 daemon 轮询线程每 **15 秒**：
拿锁 → 通过 `私信控制台.py` 的 `run()` 跑一轮 → 写心跳。它和计划任务**用的是同一把锁**，
所以两者永远不会同时扫。

### 7.3 为什么必须用 vbs 启动（三层防线）

**根因**：这个 uv 造的 venv 里 `python.exe` 和 `pythonw.exe` **是同一份复制**
（都是 `subsystem=3` console，各 45568 字节）⇒ 直接启动任何一个都会带一个黑框控制台窗口，
"换成 pythonw" 完全没用（实测过）。

| 层 | 做法 |
|---|---|
① 源头 | `启动控制台.vbs` 用 `WshShell.Run(cmd, 0, False)`（window style 0）静默启动；快捷方式指 `wscript.exe "<vbs>"` |
② 兜底 | 从终端 / 双击 `.py` 起的：换到 venv 的解释器 + `CREATE_NO_WINDOW` 重开自己，原进程退出 |
③ 再兜底 | `hide_own_console()`：`GetConsoleProcessList` 里**只有自己**才 `ShowWindow(hwnd, 0)`；还挂着 cmd/pwsh 就不动（那是你的终端） |

vbs 必须写成 **UTF-16 LE + BOM**，否则 wscript 按 ANSI 读 UTF-8 会把中文路径读坏。
模板在 `patches/launcher/`，由 `应用补丁.py` 生成实际文件。

### 7.4 单实例

`tray.pid` + `OpenProcess` 判活；→ 双击第二次不会冒出第二个图标。
⚠️ **绝不用 `os.kill(pid, 0)`**：Windows 上那等价于 `TerminateProcess`，会把进程直接杀掉。

### 7.5 宿主

「启动宿主」= `node <dsh bin> web`（detached、无窗口），起完轮询端口直到活（实测约 12 秒）。
「宿主在跑」靠 **端口探测**（`127.0.0.1:3080` 能连上就算），不看进程名 —— 之前试过
`/api/bili-duty/*`，那个接口要鉴权（401），不猜了。

### 7.6 图标是怎么抠的

托盘和窗口用的是 `图标.png`（512×512，透明底），`图标.ico` 给桌面快捷方式。抠图有三步，
**难点不在"挖洞"，在两处细节**：

```
① 找背景：原图不是内切正圆，图案边缘溢出到画面四边（实测 y=313 那行宽 1254 全满），
   四角是 253~255 的近白色 + 压缩噪点
   ⇒ 不能用"画个圆洞"的掩膜（会切掉内容或留白圈）
   ⇒ 改成 **从四角泛洪**：与四角连通的近白像素（容差 14）判为背景

② 抗锯齿：背景掩膜直接二值化，边缘会是硬切的锯齿
   ⇒ 掩膜做 0.7px 高斯，得到 1~254 的 alpha 过渡带（实测 1980 个像素）

③ 消白毛边（最关键的一步）：边缘像素本来是抗锯齿与白底混合的
       c_观测 = a·c_前景 + (1-a)·255
   只把外面设透明、颜色不动，贴到深色背景上就会显出一圈白边
   ⇒ 对边缘带反解回前景色：c_前景 = (c_观测 - (1-a)·255) / a
```

自测里专门盯这几条（`测托盘.py` ⑦）：四角 alpha 必须全 0、中心必须 255、
边缘必须有半透明过渡、`load_icon(64)` 必须与 `图标.png` 缩放结果逐像素一致
（否则说明退回了代码里画的那个备用方块）、ICO 必须同时含 16 和 256。

> 找不到 `图标.png` 时有兜底：`load_icon()` 用 PIL 现画一个蓝底方块，不报错、照常起托盘。

## 8. 对账补记 `对账补记.mjs`

三份数据对账：**判重表 `seen.md`**（流水账，最不容易错）× **日报 `out/<日期>.md`**（给人看的）。

```
① seenPicked()  解析 seen.md 的表格行，挑出 status == 挑了 的 {date, bvid, title, up}
② reportBVs()   正则 ^###\s*(BV[0-9A-Za-z]{10}) 收集报告里已有的
③ 差集          判重表有、报告没有 ⇒ 要补
④ 核对标题      最多 25 条，逐个查 view 接口拿真标题，算
                ratio = LCS(标题a, 标题b) / min(len)   ≥ 0.35 才算对得上
                对不上 ⇒ 补记时挂一条 ⚠️（链接按判重表原样保留，不自动改）
⑤ 插入位置      **插在第一个 `## 投递` 之前**（宿主只砍那个位置之后的），不是追加到末尾
```

幂等：已经写进报告的 BV 不会被重复补；`--dry` 只报差多少，`--days N` 可以连补几天。

## 9. 画像：它凭什么觉得"你大概会喜欢"

### 9.1 为什么收藏夹是有效信号

默认收藏夹 4555 条、跨 6.2 年。**"随手存"本身也是行为** —— 存的那一刻你觉得值得回看。
所以画像不是问你"喜欢什么"，而是从收藏史里量出来：

```
收藏夹全量（分页）──▶ 用 TOPICS 正则表分类 ──▶ 主题分布
                                          │
                       与 BASELINE.json 比 ──▶ 标出：冒头 / 升温 / 冷却 / 消退
```

`TOPICS` 是**正则表**（东方Project / 绘画过程 / 原神 / 泰拉瑞亚 / 学习升学 / 我的世界 / 音乐 /
马尔福·HP / 周杰伦 / 美食 / ASMR / 崩铁 / 绝区零 / Gal·AVG），`已失效` 的视频单独排除。
改表要同步 `BASELINE.json`，否则"增量"会全是假信号。

### 9.2 时效性 vs 长跨度

兴趣有两种：**这三个月在追的**（有热度）和**跨了三年的稳定偏好**（定方向）。
前者用增量对比看，后者要**均匀抽样**：

```
深页抽样.mjs：全 228 页里每 STEP(=6) 页取一页 ⇒ 约 760 条贯穿整个收藏史
            ⇒ 得到"这个兴趣最早出现在哪一年、连续多少年还有"
```

结论直接写进 `画像-长跨度分析.md`，用来决定某个词该不该常驻关键词表。

> 这一层是**离线、手动**的（不在每分钟的循环里）：兴趣的时效性是月级变化的，
> 天天重算既费钱又没有新信息。

## 10. 账单 `刷视频账单.mjs`

- **数据源**：DSH 的会话记录（多帧 zstd 的 jsonl，按 magic `28 b5 2f fd` 切帧解压），

## 11. 偏好渲染 `偏好.mjs`

追问回来的标签以前**只写进 `判据统计.json`，没有任何东西读它** ⇒ 你认真选了"选题妙/制作精良"，
选片逻辑完全不知道 ⇒ 表现成"我回了，但什么都没变"。

```md
<!-- PREFS:BEGIN 自动生成，别手改 -->

## 他给 -1 分时说的「差在哪」

<!-- PREFS:END -->
```

## 12. 配置与取值优先级

所有脚本统一：**环境变量 > `local.json` > 默认值**。

| 变量 | 作用 |
|---|---|
`BILI_DUTY_HOME` / `BILI_SCORING_HOME` | 运行时目录（默认 `~/.dsh/bili-duty`） |
`BILI_OWNER_UID` | 接收私信的账号 uid（填在 `local.json`） |
`BILI_NODE` / `BILI_DSH_BIN` | node 与 dsh 的路径（找不到就走 `local.json`） |
`BILI_SKIP_MSG_KEYS` | 控制台 → 评分 的交接：这些消息不是评价 |
`BILI_MCP_TOOLS` | 插件 → MCP 的工具白名单（见 §4.2） |

值班轮**单独走一份 settings**（`duty-settings.yaml`）：
`agent-default-model` 这类服务的**用户层永远盖住组合配置** ⇒ 只要 `~/.dsh/settings.yaml` 里有它，
`--patch` overlay 里的那条就永远不生效，必须把 profile 的 `settings` 指到另一份文件。
那份文件里要**重新声明 provider 路由**（`NO_ADAPTER`）、`input: [text, image]`（否则画面会被跳过）、
`reasoningEfforts`（否则 `UNSUPPORTED_REASONING_EFFORT` 起不来）。

### `config.json` 里真正影响行为的几项

| 键 | 作用 | 备注 |
|---|---|---|
`keywords[]` | 搜索方向 | 上限 24；估值闭环直接改这里，下一轮 `refreshCfg` 就读到 |
`excludeWords[]` | 屏蔽词 | 投递闸门用，命中就发不出去 |
`perDay` | 每天挑几条 | 额度按日报 `###` 行数扣 |
`peakValley` / `noon` / `night` | 开窗时间 | 决定值班轮什么时候跑 |
`searchSort` / `searchPages` / `fetchPerRound` | 召回策略 | 建议 `click` + 多页；见 §4.3 |
`manualMax` / `manualCooldownMin` | 手动「跑一轮」的额度与冷却 | 托盘/DSH 里点按钮时用 |
`dmMode` | `off` / `only` / `both` | `only` = 只发私信，**评论工具因此不下发**（§4.2） |
`autoComment` / `replyToComments` | 评论通道 | 默认关；关着时 `bili_reply` 不在白名单里 |
`transcribe` / `asrModel` | 无字幕时本地转写 | 默认关（贵且慢） |

## 15. 踩坑记录

| # | 踩的坑 | 正确做法 |
|---|---|---|
1 | **BV 号大小写敏感**：`BV1Ms411m7Pf`（东方原曲合集 793P）与 `BV1ms411m7Pf`（【兽人】I GOT YOU）是两个真实视频 | 发私信前做链接体检：真标题 vs 段落文字相似度，对不上就拒发并回报真实标题 |
2 | **`agent-default-model` 是「settings 用户层 > 组合配置」** | 只要 `settings.yaml` 里有这节，`--patch` 的同一条永远不生效；要单独指定模型得在 profile 层改 `settings` 的 `config.path` |
3 | **uv 建的 venv 里 `pythonw.exe` 不是无窗口版**（PE `subsystem=3`，跟 `python.exe` 同一份复制） | `wscript` + `WshShell.Run(cmd, 0, …)`；注意 pythonw 下 `sys.stdout` 是 `None`，`print()` 会崩 |
4 | **全角 `＝` 让 11 分凭空消失**：`3＝11 有深度` 被当成闲聊 | 宽度映射（`−0xFEE0`）做归一化；**不能**用 NFKC（会把 `，` 改成 `,`） |
5 | **日报被回滚**：某轮挑的整批没进报告 | 补丁修 `lastIndexOf`，同时用对账补记每分钟兜底 |
6 | **`.gitignore` 行尾的 `#` 不是注释**：`local.json  # 说明` 会变成一条永远匹配不上的规则 | 规则独占一行（差点把本地数据文件一起提交） |
7 | **1 分钟扫描要跨进程互斥** | `O_EXCL` 锁文件；判"值班轮在不在跑"只看 `run-lock.json` 的 `pid`，不能看文件新旧 |
8 | **`--simulate` 曾经写真实配置**（预览里改了闸门上限） | `SIMULATE` 全局让所有落盘空转，测试专门盯这条 |
9 | **指令被当成评价吞掉**：`加词：可玩性强` 静默记账 | 关键词指令的判断**排在评价之前** |
10 | **判断进程存活不能用 `os.kill(pid, 0)`** | Windows 上它是 `TerminateProcess`（会把进程杀掉）⇒ 用 `OpenProcess` + `GetExitCodeProcess` |
